# Install Node Banana

You can install the desktop app or run the app from source in a browser.
These guides describe `develop`, including features that are not yet in a release.
In these guides, **Settings** means the **Nb → Project settings** dialog.

| Option | Use it when | You need |

## Install the desktop app

The desktop app is a preview on `develop` and is not part of version 1.10.0.
Only the Mac app is published; a Windows build is coming soon.
Mac builds can be signed and notarized; default local packaging remains unsigned.

A ZIP is a compressed archive.
Preview packages include the local server, so you do not need Node.js, npm, or the app repository.

### macOS on Apple Silicon

A DMG is a macOS disk image.

1. Open the DMG and drag **Node Banana** into **Applications**.
2. Alternatively, extract the ZIP and move the app into **Applications**.
3. Open the installed app.
4. If macOS blocks a trusted unsigned preview, use **System Settings → Privacy & Security → Open Anyway**.
5. Enter provider keys during setup or in **Settings → Providers**.

Available installers depend on the published release and its attached files.
For updates and recovery, see [Desktop App](/guides/desktop).

### Windows

A Windows build is coming soon.
It was held back from the release until it runs as well as the Mac app.
Until then, run Node Banana on Windows [from source](#install-from-source).

## Install from source

Use Git, npm, and Node.js 22.12 or newer.
This Node version also supports the desktop tooling.

1. Clone the app repository and select `develop`.

```bash
git clone --branch develop https://github.com/shrimbly/node-banana.git
cd node-banana
```

2. Install the dependencies from the lockfile.

```bash
npm ci
```

3. Start the browser app.

```bash
npm run dev
```

4. Open `http://localhost:3000`.

The browser app uses the custom server in `server.js`.
If port 3000 is occupied, set `PORT` before the command.

```bash
# macOS or Linux
PORT=3001 npm run dev
```

```powershell
# PowerShell
$env:PORT = "3001"
npm run dev
```

## Add provider keys

An API key authorizes requests to a provider account.
Generation sends the relevant prompts and media to the selected provider.
Local files and a local editor do not make remote generation offline.

1. Complete the first-run welcome step.
2. Enter a key for each provider you plan to use.
3. Choose your default models.
4. Select **Start tutorial**, or select **Skip** to open the editor.

You can change keys later in **Nb → Project settings → Providers**.

You only need keys for the providers you use.
The [Agent](/guides/agent#start-with-agent) uses Claude Code or Codex account sign-in separately from these keys.
OpenAI supplies image and text models.
See [Models and pricing](/guides/models-pricing) for the complete provider list.
[Providers](/guides/models-pricing#providers) lists each provider's environment variable.
For the ComfyUI key and backends, see [ComfyUI](/guides/comfyui#one-key-for-cloud-and-hosted-models).

<Callout type="info">
  In browser mode, keys entered in Settings stay in browser storage and override environment keys.
  The desktop app encrypts stored credentials in its own profile.
</Callout>

### Use an environment file instead

1. Create `.env.local` in the app repository root.
2. Add only the variables for your selected providers.
3. Restart the app after you change the file.

```env filename=".env.local"
GEMINI_API_KEY=your_gemini_key
OPENAI_API_KEY=your_openai_key
ANTHROPIC_API_KEY=your_anthropic_key
COMFY_API_KEY=your_comfy_key
COMFY_CLOUD_API_KEY=your_comfy_key
REPLICATE_API_KEY=your_replicate_key
FAL_API_KEY=your_fal_key
KIE_API_KEY=your_kie_key
WAVESPEED_API_KEY=your_wavespeed_key
```

These values are placeholders.
Keep your real keys out of shared workflow notes and public repositories.
