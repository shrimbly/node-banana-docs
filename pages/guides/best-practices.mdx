# Best Practices

## Build one working path first

1. Add the minimum inputs and one generation node.
2. Check its model and provider key.
3. Run the node and inspect the result.
4. Add the next processing step.
5. Save the project before you expand it into a batch.

A small workflow makes missing inputs and model errors easier to locate.
Use **Run selected node only** or **Run from selected node** for focused checks.

## Reuse prompts

A Prompt node can define a named variable.
A Prompt Constructor uses names such as `@subject` and `@style` in a shared template.
Connect the source Prompt nodes to the constructor before you run it.
The constructor editor can copy the resolved preview for inspection.

```text
Prompt: subject ─┐
                ├→ Prompt Constructor → Generate Image
Prompt: style ──┘
```

An LLM Generate node can turn an instruction into prompt text.
Name the subject, composition, light, and changes that you want.
Check the generated text before a large batch.

## Compare two models

A Router passes one source to several downstream nodes.
An Image Compare node shows two image results with a slider.

```text
                  ┌→ Generate Image A ─┐
Prompt → Router ──┤                    ├→ Image Compare
                  └→ Generate Image B ─┘
```

Keep the prompt and references the same to compare model outputs.
The multi-select toolbar can change the model across several selected generators.

## Process a list with Array

1. Enter or connect a list of prompts to an Array node.
2. Choose the delimiter, newline, or regular-expression split mode.
3. Check the parsed items.
4. Enable **Batch** and connect the Array to a supported generator.
5. Run the workflow.

Array batches run sequentially through Generate Image, Generate Video, Generate Audio, or LLM Generate.
Generate 3D does not use this batch path.
For separate editable branches, use **Auto-route to Prompts** instead.
An Output Gallery collects image and video results.

## Split an image into cell workflows

Split Grid creates one node set for each image cell.
Each axis supports up to 16 cells.

1. Connect a source image to Split Grid.
2. Set the rows and columns.
3. Adjust the slice lines for unequal cells.
4. Select **Open cell editor** and build the template for one cell.
5. Choose a grid, vertical, or horizontal node layout.
6. Split the image to create each cell's node set.

The cell editor supports all node types, including video generation.
A shared downstream Router can collect the template's terminal outputs.
See [Split Grid](/nodes#split-grid) before you change an existing materialized layout.

## Make execution deliberate

A Switch enables selected branches without removing their noodles.
Optional input nodes let an unused branch stay empty.
Locked groups skip completed or inactive parts of the workflow.
Hidden noodles still run, so hiding is only a visual change.

A loop noodle repeats an upstream path.
Set a small iteration count first and inspect the result.
A fallback model retries failed generation with another model and its own settings.
Check that the fallback's provider key and inputs are available.

## Organize a large canvas

Use node names and comments that describe each step's purpose.
Groups keep related nodes together.
The multi-select toolbar controls stacking, grid placement, and spacing.
Noodle labels and bundles make shared inputs easier to trace.

Use [saved ComfyUI nodes](/guides/comfyui#save-and-reuse-a-configured-node) for workflows with repeated ComfyUI settings.
Use **Output Gallery → Extract** to turn gallery items into reusable input nodes.

## Control cost and preserve work

Check [Models and pricing](/guides/models-pricing) before you run batches, loops, or fallback chains.
The app's cost totals do not cover every provider or model.
The provider account remains the record of billed usage.

Save important changes with **Nb → Save project**.
For portable projects, keep workflow files and external media folders together.
For embedded images, enable **Settings → Project → Embed images as base64**.
Large embedded workflows use more memory.

The [desktop app](/desktop) provides crash recovery as well as normal project saves.
